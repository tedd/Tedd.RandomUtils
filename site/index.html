Purpose-specific generators

Choose semantics
before speed.

The implementations share familiar method names but serve materially different requirements. Cryptographic work requires an operating-system-backed generator; deterministic or throughput-oriented work does not.

+

Random extensions

Add booleans, all integer widths, floats, and strings to an existing System.Random instance.

∞

ConcurrentRandom

Expose static, synchronized access when multiple threads need a shared pseudorandom source.

◇

CryptoRandom

Present a Random-like interface over RandomNumberGenerator for security-sensitive values.

◇∞

ConcurrentCryptoRandom

Combine operating-system random bytes with a shared thread-safe entry point.

↯

FastRandom

Use a small Lehmer-based pseudorandom generator where throughput matters and cryptographic unpredictability does not.

AZ

Random strings

Generate fixed-length strings from caller-selected characters alongside complete primitive value ranges.

Selection guide

Match the generator to the consequence.

A faster pseudorandom sequence is not a substitute for cryptographic unpredictability. Conversely, an OS-backed generator is unnecessary for simulations or visual effects that only need ordinary distribution.

Familiar call sites

Move between sources
without relearning the surface.

Use explicit generator names to make concurrency and security choices visible at the call site.

EXTENSIONS
using Tedd;

var random = new Random();
var id = random.NextUInt64();
var token = random.NextString("abcdef", 16);
CRYPTOGRAPHIC
using Tedd.RandomUtils;

using var random = new CryptoRandom();
var nonce = new byte[32];
random.NextBytes(nonce);
